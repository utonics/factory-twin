# 04. 저장소 이름 추천 받기

## 원문
> github에 등록하고 싶다. 이름을 추천해 줘

## 상황
- 애니메이션과 데이터 파이프라인이 동작하고 아직 한 번도 커밋하지 않은 상태

## 의도
- 결과물을 저장소에 올리기 전에 이름부터 정한다

## Claude Code가 한 일
1. 후보 4개를 표로 제시(`factory-twin` 추천, `smart-factory-twin`, `factory-twin-3d`, `virtual-factory-sim`)
2. 저장소 설명 문구도 함께 제안
3. 이후 절차(패키지 이름 맞추기 → diff 검토 → 커밋 → 푸시)를 미리 설명
4. 외부에 게시되는 작업이므로 **공개 범위(public/private)와 푸시 방식(브랜치 그대로/main 병합)을 되물음**

## 사람이 정한 것
| AI의 질문 또는 제안 | 사람의 결정 |
|---|---|
| 이름 추천 `factory-twin` | 채택(직접 GitHub에 생성) |
| public / private | private |
| 브랜치 그대로 / main에 합쳐서 | main에 합쳐서 |

## 검증
- 해당 없음(제안 단계)

## 결과
- 커밋: 없음
- 산출물: 이름·설명 후보

## 방법론 포인트
- **외부에 영향을 주는 작업(게시·배포·삭제)은 AI가 먼저 묻게 한다.** 전역 규칙의 "커밋·푸시는 사용자 요청 시에만"이 이 질문을 만들었다
- 저장소 생성처럼 계정 권한이 필요한 일은 사람이 직접 하고, AI는 그다음을 맡는다

## 교육용으로 다듬은 프롬프트
```text
Context: 지금 작업 폴더의 결과물을 GitHub에 올리려 한다.
Goal: 저장소 이름과 설명을 추천해 달라.
Constraints: 아직 아무것도 생성·푸시하지 않는다. 결정이 필요한 것은 질문으로 남긴다.
Output: 이름 후보 표(추천 1개 표시), 설명 문구, 이후 절차.
Verify: 해당 없음.
```
