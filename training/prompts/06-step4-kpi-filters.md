# 06. 단계 호출 — "원래 프롬프트 4단계 진행하자"

## 원문
> 원래 프롬프트 4단계 진행하자

## 상황
- 01번에서 준 마스터 프롬프트의 4단계(사이트 선택, KPI 4종, 필터, 어두운 테마)를 진행할 차례

## 의도
- 단계 번호만으로 다음 작업을 지시한다. 세부 해석은 AI에게 맡긴다

## Claude Code가 한 일
1. 템플릿(창고 앱)과 공장 사이에 해석이 갈리는 지점 2개를 찾아 **AskUserQuestion으로 질문**(작업 시작 전)
2. 4단계를 공장에 맞게 번역
   - 사이트 선택 → 공장 내 구역 선택(카메라 부드럽게 이동)
   - 정시 배송률 → 출하 오더 납기 준수율
   - 도크 사용·운행 트럭 → 출하 도크 2개
   - 재고 부족 → 창고 원자재·라인 투입 자재 알람
   - 필터 → 설비·AGV 상태별 보기(장면에서 나머지는 흐리게), 지연 오더만 보기
3. 새 데이터 생성: 출하 오더(고객·수량·납기), 창고 재고(정기·긴급 입고)
4. **수치 튜닝을 여러 시드로 반복**: 오더 간격 130초(100% 또는 20%로 극단) → 150초(전부 100%) → 210초 채택(0.75~1.00), 재고 알림 비율 15~44% → 0~11%
5. 테스트로 발견: 처음부터 접안해 있던 트럭을 처리기가 모름 → 가상 공장이 첫 진행 시 초기 상태 전체를 발행하도록 수정
6. 디버그 로그로 발견: 흐림 효과가 화면에 안 보임 → 셰이더 재컴파일(`needsUpdate`) 누락 수정

## 사람이 정한 것
| AI의 질문 또는 제안 | 사람의 결정 |
|---|---|
| '사이트 선택'을 공장 내 구역 선택 / 공장 여러 개로 | 공장 내 구역 선택(추천) |
| 템플릿의 어두운 테마 / 기존 밝은 테마 / 전환 기능 | 밝은 테마 유지(추천) |

## 검증

- 브라우저: 구역 이동, 필터 흐림, 오더 탭·지연 필터, 창고 클릭 패널 확인

## 결과

- 산출물: 구역 선택, KPI 5개, 필터, 오더·도크·재고 데이터

## 방법론 포인트
- **단계 호출이 통하는 이유**: 01번에서 전체 로드맵을 맥락으로 줬기 때문
- **해석이 갈리는 결정은 시작 전에 묻는다.** 작업량이 크게 달라지는 선택(공장 1곳 vs 3곳)을 AI가 혼자 정하지 않았다
- **시뮬레이션 데이터는 "그럴듯함"을 수치로 맞춘다.** 시드 여러 개로 돌린 표를 보고 범위를 정한다

## 교육용으로 다듬은 프롬프트
```text
Context: 마스터 프롬프트의 4단계(사이트 선택·KPI·필터·테마)를 우리 공장에 적용할 차례다.
Goal: 4단계를 공장 도메인에 맞게 번역해 구현한다.
Constraints: 해석이 갈리거나 작업량이 크게 달라지는 결정은 시작 전에 질문한다. 새 데이터는 기존 가상 데이터 구조(메시지 → 처리기)를 따른다.
Output: 템플릿 항목 → 공장 항목 대응표, 바꾼 파일 목록.
Verify: 새 지표가 여러 시드에서 현실적인 범위인지 표로 보여 주고, 테스트·타입 체크·빌드와 브라우저로 확인한다.
```
