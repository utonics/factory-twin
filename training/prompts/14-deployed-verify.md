# 14. 운영 확인 — "1번으로 완료함"

## 원문
> 1번으로 완료함

## 상황
- 사람이 Vercel 대시보드에서 저장소를 Import해 운영 배포를 마침

## 의도
- 배포가 끝났음을 알리고, 결과 확인을 맡긴다

## Claude Code가 한 일
1. Vercel CLI로 배포 상태(Ready, Node 24.x)와 운영 주소 확인
2. **운영 주소가 내려주는 번들 파일 이름 = 로컬 최신 빌드**인지 대조해 최신 커밋이 배포됐는지 확인
3. Playwright로 운영 주소 접속: 로딩 0.4초, 60 FPS, 콘솔 오류 0건, 클릭·패널 동작
4. **확인 중 버그 발견**: 카메라를 안 움직였는데 상단 구역 선택이 "직접 이동한 시점"으로 바뀜
5. 재현 시도: 로컬 0회, 운영 9회 중 2회. 입력 이벤트를 기록하며 재현했지만 원인 신호는 특정하지 못함
6. 원인을 못 찾았다고 밝히고, **판단 기준을 바꿈**: "입력 시작 신호"가 아니라 "조작 중 카메라가 실제로 0.5m 넘게 움직였을 때"만 해제
7. 6가지 동작(처음 접속·구역 선택·클릭만·드래그·재선택·휠)을 브라우저로 확인한 뒤 커밋 여부를 물음

## 사람이 정한 것
| AI의 질문 또는 제안 | 사람의 결정 |
|---|---|
| 수정을 커밋하고 main에 반영할지 | "네"(15번) |

## 방법론 포인트
- **배포 후에도 운영 주소로 다시 검증한다.** 로컬에서 안 보이던 버그가 운영에서 나왔다
- **원인을 못 찾으면 못 찾았다고 보고하게 한다.** 그다음 증상 우회가 아니라 "판단 기준 자체가 틀렸는지"를 본다
- 배포된 것이 정말 최신인지 번들 이름 같은 증거로 확인한다

```text
Verify: 배포 번들이 로컬 최신 빌드와 같은지, 콘솔 오류·FPS·주요 클릭 동작을 확인한다. 이상이 있으면 재현 조건을 찾고, 못 찾으면 그렇게 보고한다.
```
