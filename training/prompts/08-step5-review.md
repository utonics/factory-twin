# 08. 독립 점검 — "원래 프롬프트 5단계 진행하자"

## 원문
> 원래 프롬프트 5단계 진행하자

## 상황
- 마스터 프롬프트 5단계: 시니어 엔지니어처럼 점검(버그·성능·안 쓰는 코드), 인스턴싱, 60 FPS, 빌드·타입 체크 결과 보고, 새 기능 금지

## 의도
- 기능을 더하지 않고 품질만 끌어올린다

## Claude Code가 한 일
1. 코드 점검을 **서브에이전트 2개에 병렬로** 맡김: ① 시뮬레이션·데이터 로직 ② 3D 장면·UI. "근거가 없으면 버리라"고 지시
2. 그동안 자신은 **성능 기준치 측정**: Playwright에 측정 스크립트를 주입해 FPS, 프레임당 JS 시간, 그리기 호출 수를 측정
3. 개발 서버의 끊김이 개발 모드 React 때문인지 가르려고 **프로덕션 빌드로 다시 측정** → 프로덕션은 느린 프레임 0건
4. 리뷰 결과 반영
   - 버그 12건: 알람 디바운스, AGV LED, 흐림 필터, 빈 도크 클릭, 구역 선택, 차트 툴팁, 키보드 접근 등
   - 성능: 반복 메시 인스턴싱, 가는 부품 그림자·포인트 라이트 제거, 일시정지 중 UI 갱신 생략, 프레임당 객체 생성 제거
   - 안 쓰는 코드: 필드·함수·죽은 분기·export 정리
5. 시드에 기대던 테스트가 실패 → 건너뛰지 않고 **결정적인 테스트로 다시 작성**
6. 고치지 않고 남긴 것을 보고: 충전소 단일 차선 정체(구조 변경 필요), 필터 첫 사용 끊김

## 사람이 정한 것
| AI의 질문 또는 제안 | 사람의 결정 |
|---|---|
| (질문 없이 진행) 범위: 새 기능 금지 | 결과 확인 후 커밋 지시 |

- 키보드 동작(Enter로 공정 단계 선택, 알람 확인만 처리) 브라우저 확인

## 방법론 포인트
- **자기 코드 리뷰는 관대하다 → 관점을 나눈 별도 에이전트에게 맡긴다**
- **성능은 프로덕션 빌드로 잰다.** 개발 모드 수치로 판단하면 엉뚱한 곳을 고친다
- **"남긴 것"을 보고하게 한다.** 범위 밖 과제가 다음 프롬프트(10번, 16번)의 출발점이 됐다

## 교육용으로 다듬은 프롬프트
```text
Context: 기능 개발은 끝났다. 이제 품질을 점검한다.
Goal: 버그·성능 문제·안 쓰는 코드를 찾아 고친다. 반복 메시는 인스턴싱한다. 60 FPS를 확인한다.
Constraints: 새 기능 금지. 점검은 관점별 서브에이전트에게 나눠 맡기고, 근거 없는 지적은 버린다. 테스트를 건너뛰어 통과시키지 않는다.
Output: 발견 목록(심각도순), 수정 전후 측정표, 고치지 않고 남긴 것.
Verify: 프로덕션 빌드로 FPS·그리기 호출을 측정하고, 테스트·타입 체크·빌드 결과를 그대로 보여 준다.
```
