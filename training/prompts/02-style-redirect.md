# 02. 진행 중 방향 교정 — "이미지 스타일만 참조"

## 원문
> [참고 이미지 첨부: 창고 관리 앱 컨셉 화면]
> 이미지 스타일만 참조하고 너가 구현할 수 있는 스마트 팩토리로 검토해 진행하자

## 상황
- 01번 작업 도중(패키지 버전을 확인하던 시점)에 보낸 메시지. Claude Code는 작업을 멈추지 않고 이 메시지를 반영해 이어 갔다
- 원래 템플릿은 "어두운 산업 테마 + 앰버" 였고, 첨부 이미지는 밝은 흰 카드형 UI였다

## 의도
- 참고 이미지에서 **스타일만** 가져오고, 내용(창고 앱)은 따르지 말라는 경계 설정
- 구현 범위는 AI가 실제로 만들 수 있는 수준에서 판단하게 한다

## Claude Code가 한 일
1. 밝은 아이소메트릭 장면, 흰 카드형 UI, 파란 포인트 색, 노란 차량으로 스타일 방향을 바꿈
2. 공장 구성은 01번에서 잡은 설계(창고 → AGV → 2개 라인 → 출하)를 유지
3. 참고 이미지의 UI 배치(상단 KPI 카드, 오른쪽 상세 패널, 하단 목록)를 공장 정보에 맞게 옮김

## 사람이 정한 것
| AI의 질문 또는 제안 | 사람의 결정 |
|---|---|
| 템플릿의 어두운 테마 vs 첨부 이미지의 밝은 스타일 | 이미지 스타일(밝은 테마) |

## 검증
- 01번과 같은 턴에서 화면 캡처로 확인

## 결과
- 커밋: 4a6e234에 포함
- 산출물: 밝은 테마의 화면 구성

## 방법론 포인트
- **작업 중에도 끼어들 수 있다.** 다음 턴까지 기다리지 않고 진행 중에 방향을 바로잡는 것이 비용이 가장 적다
- **참고 자료에는 "무엇을 참고하고 무엇은 따르지 말지"를 함께 준다**
- 외부 이미지·영상은 교재에 그대로 쓰지 않는다(저작권). 이번 교재에서도 컨셉 이미지는 빼고 말로만 설명한다

## 교육용으로 다듬은 프롬프트
```text
Context: 첨부한 이미지는 다른 앱(창고 관리)의 컨셉 화면이다.
Goal: 색·레이아웃·카드형 UI 같은 시각 스타일만 참고해 우리 스마트 팩토리 화면에 적용한다.
Constraints: 이미지의 내용(창고·트럭 등)은 따르지 않는다. 지금 구현 가능한 범위에서 판단한다.
Output: 어떤 스타일 요소를 가져왔는지 목록.
Verify: 브라우저 화면 캡처로 확인한다.
```
