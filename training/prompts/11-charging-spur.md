# 11. 추천안 구현과 로컬 병합

## 원문
> 추천 방안으로 하고 로컬의 브렌치도 머지하자.

## 상황
- 10번에서 분기선 방식을 설명받음

## 의도
- 추천안을 구현하고, 이번에는 원격뿐 아니라 로컬 main까지 병합한다

## Claude Code가 한 일
1. 두 작업 폴더가 깨끗한지 확인
2. **구현 전에 기준치를 측정**(4시간·시드 3개): 본선 정체, 충전 AGV 바로 뒤 정체, 최저 배터리, 생산량
3. 충전 베이 3칸 구현: 분기점 접근 시 빈 베이 예약 → 분기선에서 충전 → 본선 앞뒤 안전거리 확보 시 합류
4. 기존 안전거리 테스트가 실패 → 분기선 AGV까지 본선 위치로 비교하던 테스트를 **본선 AGV끼리만 비교하도록 고치고**, 검사 간격을 0.1초로 줄여 합류 순간까지 포함. 분기선 전용 테스트 추가
5. 효과 측정에서 납기 준수율이 0.89 → 0.67로 떨어진 것처럼 보임
   - 수정 전 코드를 임시 폴더로 꺼내 시드 8개 A/B 비교
   - 원인: 주문·입고가 공장 내부와 같은 난수를 써서 AGV 동작이 바뀌면 다른 주문이 들어옴
   - 주문·입고 난수를 분리해 같은 주문으로 다시 비교 → 0.869 vs 0.864, 차이 없음
6. 화면 확인 중 충전기가 베이 안 AGV를 가리고, 충전기 화면이 캐비닛 뒤에 숨는 것을 발견해 수정
7. 커밋 → 원격 main 푸시 → **로컬 main은 `merge --ff-only`로 병합**

## 사람이 정한 것
| AI의 질문 또는 제안 | 사람의 결정 |
|---|---|
| 분기선 구현 | 승인(10번에서) |
| 로컬 main 반영 | 병합 요청 |

## 검증
- 충전 AGV 바로 뒤 정체 859~1,081초 → 0초, 본선 정체 5,379 → 3,995 AGV·초(−26%)
- 생산량 3,720 → 3,723, 납기 준수율 0.869 → 0.864(같은 주문 흐름)
- 테스트 22개, 타입 체크·빌드, 60 FPS·그리기 호출 403

## 결과
- 커밋: e7c811c `feat: AGV 충전소를 순환로 밖 충전 베이로 분리` (14개 파일)

## 방법론 포인트
- **고치기 전에 기준치부터 잰다.** 그래야 "좋아졌다"를 말할 수 있다
- **지표가 나빠지면 비교 조건부터 의심한다.** A/B는 같은 입력에서만 의미가 있다
- **테스트를 고칠 때는 이유가 있어야 한다.** 이번엔 테스트의 전제(모든 AGV가 본선 위)가 바뀐 것이었다

## 교육용으로 다듬은 프롬프트

```text
Context: <추천안>을 구현하기로 했다.
Goal: 구현하고 원격·로컬 main에 반영한다.
Constraints: 구현 전에 기준치를 측정한다. 테스트를 수정해야 하면 이유를 먼저 설명한다.
Output: 수정 전후 비교표, 바뀐 파일, 커밋 해시.
Verify: 같은 입력 조건으로 A/B 비교하고, 테스트·타입 체크·빌드·FPS를 확인한다.
```
