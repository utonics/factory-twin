# 16. 남은 과제 처리 — "필터 첫 사용 시 끊김도 해결하자"

## 원문
> 필터 첫 사용 시 끊김도 해결하자

## 상황
- 08번 점검에서 남긴 두 번째 과제

## Claude Code가 한 일
1. **기준치 측정**(프로덕션 빌드, 3회): 필터 첫 사용 시 새 셰이더 3개 컴파일, 최대 프레임 35~39ms / 두 번째 사용은 0개, 약 20ms
2. 원인: 흐림 처리 때 재질을 투명으로 바꾸면 투명용 셰이더를 그 자리에서 컴파일
3. three.js 소스에서 `compile(scene, camera, targetScene)`이 조명·안개는 메인 장면 것을 쓴다는 것을 확인
4. 해결: 앱 시작 직후, 화면에 그리지 않는 임시 그룹의 복제 재질로 투명용 셰이더를 **비동기(compileAsync)로 미리 컴파일**
5. 시작 시점에 새 끊김을 만들지 않는지 프레임별로 기록해 확인
6. 흐림이 화면에 그대로 적용되는지 캡처로 확인

## 검증
- 새 셰이더 3 → 0개, 최대 프레임 35~39ms → 약 24ms
- 로딩 직후: 기존 초기 컴파일 프레임 외 새 끊김 없음
- 테스트 22개, 타입 체크·빌드

## 결과
- 커밋: 70ad2da `perf: 흐림 필터 첫 사용 시 셰이더 컴파일 끊김 제거` (3개 파일)

## 방법론 포인트
- **성능 수정은 "기준치 → 수정 → 같은 방법으로 재측정"이 한 세트**

- 남은 개선 효과(이 Mac에서 약 15ms)와 미검증 범위(저사양·Windows)를 함께 보고했다
