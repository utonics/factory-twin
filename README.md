# 스마트 팩토리 디지털 트윈 (FactoryTwin)

React Three Fiber로 만든 스마트 팩토리 인터랙티브 3D 애니메이션입니다.
실제 설비 대신 가상 공장이 센서 데이터와 설비 이벤트를 임의로 만들어 내고, 데이터 처리기가 이를 받아 OEE·알람·예지 보전 지표를 계산합니다.

## 실행

```bash
npm install
npm run dev        # 개발 서버
npm test           # 시뮬레이터 테스트
npm run build      # 타입 체크 + 프로덕션 빌드
```

## 공장 흐름

자재창고 → AGV → 생산라인 2개(CNC 가공 → 로봇 용접 → 비전 검사 → 자동 포장) → 팔레트 적재 → AGV → 출하 적치장 → 트럭 상차

- 설비: 사이클 타임 변동, 무작위 고장(MTBF/MTTR)과 수리, 후공정 정체·자재 대기 상태
- 컨베이어: 누적식 이송(제품 간 최소 간격 유지)
- 비전 검사: 불량 판정 시 배출함으로 밀어냄
- AGV 5대: 단방향 순환로, 차간 거리 유지, 운반 예약, 배터리 소모
- AGV 충전: 순환로 밖 드라이브스루형 충전 베이 3칸. 분기해 들어가 충전하고, 본선에 안전거리가 확보될 때 합류(충전 중인 AGV가 본선을 막지 않음)
- 출하: 도크 2개, 팔레트 6개가 차면 트럭 출발. 출발 팔레트는 납기가 빠른 오더부터 배정
- 출하 오더: 고객·팔레트 수·납기를 가진 오더가 무작위로 접수(주문·입고는 공장 내부와 분리된 난수를 써서, 같은 시드면 같은 주문이 들어옴)
- 자재창고: 원자재 재고가 AGV 출고로 줄고 정기 입고로 채워짐. 부족하면 긴급 발주

## 화면 기능

- 상단 바 구역 선택(전체·자재창고·1라인·2라인·출하장·AGV 충전소): 카메라가 해당 구역으로 부드럽게 이동
- KPI: 생산 완료, OEE, 납기 준수율, 도크 사용·운행 트럭, 재고 부족 알림
- 필터: 설비·AGV 상태별 보기(장면에서 나머지는 흐리게), 지연 오더만 보기
- 객체 클릭 시 상세 패널(상태, OEE, 예지 보전, 센서·재고 추이)

## 데이터 흐름

```
시뮬레이터(설비 동작·마모) → 가상 공장(가상 센서 1초 샘플 + 설비 이벤트) → 메시지 버스 → 데이터 처리기 → UI
```

- **가상 센서**: 설비 유형별 진동·온도·부하·회전수·토크·용접 전류·조명 광량·공압, AGV 배터리·속도 (`src/data/sensorCatalog.ts`)
- **마모 모델**: 가공할수록 마모가 쌓여 센서 값이 나빠지고 고장 확률이 오름. 수리하면 초기화
- **설비 이벤트**: 상태 변경, 사이클 완료(검사 결과·불량 유형), 완제품 완료(리드타임), 트럭 출발
- **처리 결과**
  - 센서 시계열(최근 10분)
  - 알람: 임계치 경고·위험, 3초 디바운스, 3% 히스테리시스, 격상·해제·확인, 설비 고장 알람
  - OEE: 설비별(가용성·성능·품질), 라인별(병목 설비 기준)
  - 5분 단위 생산량, 불량 유형 분포, 평균 리드타임
  - 납기 준수율·지연 오더, 도크 사용·운행 트럭, 재고 부족 알림(창고 재고·라인 투입 자재)
  - 예지 보전: 최근 5분 가동 데이터의 선형 추세로 건강도와 위험 임계치 도달 예상 시간 계산

메시지 토픽은 MQTT 형식(`f01/{라인}/{자산}/{telemetry|event}`)을 본떠 두었습니다.

## 폴더 구조

| 경로 | 역할 |
| --- | --- |
| `src/domain/types.ts` | 도메인 타입(레이아웃 Spec / 운영 State) |
| `src/data/factoryLayout.ts` | 공장 배치·설비 사양 |
| `src/data/sensorCatalog.ts` | 가상 센서 정의(단위·정상값·임계치) |
| `src/sim/` | 시뮬레이터, 가상 공장(센서·이벤트 발행), UI용 운영 스냅샷 |
| `src/platform/` | 메시지 버스, 데이터 처리기(시계열·알람·OEE·예지 보전) |
| `src/runtime.ts` | 시뮬레이터 → 가상 공장 → 버스 → 처리기 구성 |
| `src/store/` | Zustand 스토어(선택, 배속, 운영 스냅샷, 분석 스냅샷) |
| `src/scene/` | 3D 장면. 상태를 읽어 그리기만 하고 비즈니스 로직은 없음 |
| `src/ui/` | 상단 바, KPI, 상세 패널, 목록, 공정 흐름 |
| `tests/` | 시뮬레이터·데이터 처리 테스트 |

## 실데이터로 바꿀 때

데이터 처리기는 버스 메시지(`PlantMessage`)만 받습니다. 실제 설비 데이터를 쓰려면 `MessageBus`에 MQTT·WebSocket 수신을 연결하고 같은 메시지 형식으로 발행하면 OEE·알람·차트는 그대로 동작합니다.
3D 애니메이션은 지금 시뮬레이터 상태(`FactoryState`)를 직접 읽으므로, 이 부분은 실데이터 이벤트로 상태를 재구성하는 어댑터가 추가로 필요합니다.
